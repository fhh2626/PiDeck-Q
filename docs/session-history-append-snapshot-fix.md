# 并发追加时的会话历史快照修复

## 原因与范围

`SessionDisplayIndexStore` 将 JSONL 元数据/偏移索引与选中正文分开读取。此前正文读取前后要求 `[dev, ino, size, mtimeMs, ctimeMs]` 完全相等：正常的 `model_change` 或消息追加也会触发 `SESSION_HISTORY_CHANGED`。大于 5 MiB 的启动历史走本地读取，失败后可能只有日志，而没有历史窗口、entryId 或分页游标。

`pdbtop` 实际日志在 13:42:17.035 报此错误，JSONL 在此前的 13:42:17.011 有正常模型配置追加；新用户消息在 13:42:17.076 才追加。这与启动后的偏好应用写入相符，但日志没有标记具体抛错阶段，不能据此声称每一段现场 UI 缺失都已精确归因。实际文件旧消息仍在；修复未修改它。

另一个相邻问题是 `AgentManager.loadMessages()` 用旧正文再次查询最新文件的数量、压缩记录和版本，使消息、身份与游标可能来自不同版本。

## 修复契约

| 能力 | 修复后的行为 |
| --- | --- |
| 索引边界 | 打开描述符后固定 `[0, size)`、文件身份和版本；后续尾部不混进本次索引 |
| 正常追加 | 验证旧完整前缀 SHA-256 后可继续服务旧快照；下次请求使用新版本 |
| 正文完整性 | 各选中行与索引时的行摘要比对，不只检查同一个 entryId |
| 改写 + 增长 | 增长本身不是追加证明；旧前缀或选中行摘要不符仍拒绝 |
| 路径替换/截断/短读 | 同时校验描述符与命名路径身份；不足快照长度、零读取或版本失效拒绝 |
| 验证期间再变化 | 不把 hash 扫描期间出现的新指纹标成已验证；正文结束重新验证；最终扫描期间变化追加一次有界确认 |
| 快照投影 | 正文、角色 entryId、真实文件位置、压缩信息、`mtime:size` 版本来自同一快照 |
| 首次读取失效 | 只对 `SESSION_HISTORY_CHANGED` 重读一次；不退回全量 `get_messages` |
| 持续/权限等失败 | 有本地化错误消息，保留现有“重新打开会话重试”入口；不伪造游标或写入 exhausted |
| 生命周期 | 关闭、换路径、进程替换或更新的 load sequence 禁止旧读取重试、回写和错误提示 |
| 在途新消息 | 沿用现有保护/去重逻辑；历史完成不覆盖刚发的用户消息与回复 |

快照元数据通过 reader 内部 `WeakMap<RpcResponse, ...>` 与其本地响应绑定，不加入 Pi RPC、桌面 IPC 或持久化格式。模型/偏好写入仍由 Pi 负责，没有新增通信通道或要求所有写入暂停。

这不是任意第三方写入者下的文件系统事务/锁：读取操作完成后文件仍可变化。返回的是固定边界的已验证历史视图，不宣称返回时包含所有最新尾部。前缀检查、行摘要和变化期间的确认用于拒绝观测到的旧内容变化，不能等同于跨进程写锁。

## 资源与兼容性

- 保留 50 轮、完整轮次、最新超大轮、分页字节预算、LRU 和传输背压。
- 稳定版本不增加全文件正文读取；暖全文仍只读目标行。变化时前缀验证为 O(旧 size)，每块最多 64 KiB；确认次数有限，不等待整个文件空闲。隔离 benchmark 的 10.49/52.44 MB 文件，冷 recent/count/compaction 合计读取 **10,674,962 / 52,601,691 bytes**，暖全文各 **10,335 bytes**，全文件 `readFile` 均为 0，与此前基线一致；不是现场 Qt/WSL 性能证据。
- 正文保留既有 ≤1 MiB 相邻行合并规则及单条大消息行为。索引新增每行摘要，不缓存历史正文。
- 完整无末尾 LF、未完成尾行后续补全、UTF-8/CRLF、physical-first 重复 ID、活动分支 last-ID-wins、物理压缩记录、TS/Rust 兼容链路保持原策略。
- 没有新依赖、设置、缓存迁移、原始 JSONL 格式或公共 `mtime:size` 版本格式变化。

## 回归与红 → 绿

1. 真实 reader + 一次性 JSONL：索引扫描、stat/open 间、正文打开前、正文读取中追加；持续追加；新消息不混进旧页及其游标/版本。另验证完整无 LF 行在读期间追加下一条、半条 UTF-8 消息追加后补全、fork 仅影响下一快照、两个并发正文消费者保持各自选中的同一旧版本。
2. 原实现中正文打开前/中追加和追加用户分页失败；快照元数据接口尚不存在。旧前缀改写、改写再增长、截断保持拒绝。
3. 额外边界先测红再修复：前缀验证期间“先读旧块再改写并增长”，以及最终验证游标之后改写非选中旧行。不能把 hash 期间出现的指纹直接当作验证结果。
4. 真实公共 `AgentManager.create()` → 文件读取/投影 → 事件 → Jotai → 分页策略：>5 MiB、54 轮、有压缩的会话展示最近 50 轮并读回最早 4 轮。Pi/process 使用替身，真实 spawn/exec 禁止，HOME 与数据隔离。
5. 原 `AgentManager` 投影在独立临时 preload 中复现无 entryId，以及尾部追加后旧窗口头错从 8 变成 10；实际源文件没有为此回滚。
6. 单次失效恢复和持续失败可见错误先红后绿；实际旧前缀改写（非注入错误）触发第一次启动读失效后，从新版本恢复并读出改写后的旧轮。新发消息在正常加载及首次失败后的恢复中均保留；关闭与较新加载阻止旧失败重试/回写。恢复策略另有纯函数测试，覆盖非快照错误不重试、最多两次、结构化错误与过期所有权。
7. 既有资源测试继续验证一次冷扫描、暖定点正文、并发 single-flight、长 UTF-8 短读、无 LF/半行、父链改写、路径替换和完整轮次。
