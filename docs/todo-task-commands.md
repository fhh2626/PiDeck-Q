# Todo 任务命令

两条命令都由内置 `pi-deck-todo` 扩展提供，只约束本次任务，不是持续模式。

| 命令 | 行为 |
| --- | --- |
| `/todo [任务正文]` | 提示 Agent 先建立、再维护清单；允许提问，不自动续跑。 |
| `/todo-goal [任务正文]` | 首次成功添加待办之前允许澄清；之后程序级阻断 `ask_question`，任务未完成时尝试续跑。 |

没有正文时读取当前分支最近的用户任务，包括此前通过这两条命令明确指定的任务；没有可用任务时先显示输入框澄清。Agent 正在运行时，不用命令替换正在执行的任务，需先等待或停止。

`/plan-progress` 仍然只查看计划进度。`/todo` 不再提供查看、折叠或展开列表的旧功能；列表从会话标题处的 todo widget 查看。命令不会隐式解除计划模式及其只读限制。在计划确认框选择“先不执行”“继续规划”或关闭确认框，也会暂停 goal 的自动续跑。

## Goal 的恢复边界

- 自动续跑只依赖 Pi 的 `agent_before_settle` 安全收尾事件，通过返回上下文与续跑请求交给 Pi 调度。不会在桌面侧重发任务，也不会直接在 `agent_end` 上抢跑。
- Pi 的内建重试、压缩和已排队消息优先。续跑携带原始目标和未完成项，不清空清单，不要求重复已完成操作。
- 空清单不算完成。只有建立过清单、仍有条目且全部完成，才停止 goal 控制；清空清单不会解除提问锁定，同一 goal 内重新建表时 ID 继续递增，避免把新完成项误判为重复进展。
- 进展以本次任务中首次完成的待办 ID 为准。仅查看、追加待办或反复勾选同一项不算新进展。连续三个收尾轮次失败或没有进展后暂停；有新的完成项且本轮没有报错则重置计数。
- 任务通过 Pi 原生可取消入口启动，启动阶段和执行中的主动停止均取消自动恢复。任务替换、会话/分支切换或扩展重载使旧控制失效，旧提示不影响后续任务。
- 只恢复仍存活进程内、到达安全收尾边界的轮次；不处理进程崩溃、应用重启或无法到达该事件的启动失败。恢复历史清单不会自动恢复执行。
- 不提供该事件或不能提供可靠收尾信息的运行时（包括尚未验证的 Rust 版本）不会被强制续跑；命令启动时会说明这一限制。第三方扩展接管 `todo` 工具时，PiDeck 的任务命令不启动控制。

禁止提问不代表获得额外权限。遇到凭据、权限或安全限制时，Agent 应如实说明阻塞原因，不能绕过限制，也不能以无限重试保证完成。

任务原文以可见的 Pi 自定义目标消息保存，桌面实时记录、历史分页和会话摘要均可展示；内部约束和续跑提示仍隐藏。目标在时间线上是独立的只读轮次，使用任务气泡而不是系统诊断卡，不提供用户消息的编辑、删除或重发操作。
