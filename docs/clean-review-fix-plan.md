## Review 后追加修复计划

1. **启动容错（已完成）**：`ProjectStore.loadForStartup()` 保持项目记录读取先于 catalog 迁移；只隔离聊天目录准备和启动修正写回的失败，记录主进程 warning。项目记录读取/损坏原件保护失败仍拒绝启动；原 `load()` 和聊天目录设置命令保持严格失败契约，不静默更换用户目录。装配入口仅改为调用启动专用方法。
2. **旧 catalog 碰撞迁移（已完成）**：纯迁移策略抽到 `sessionCatalogMigration.ts`，规范化后合并同一 origin 的持久化记录。优先保留原相对路径记录的 UUID；已全部绝对化时保留最早创建记录，时间相同保留文件中的先后顺序。保留主记录的标题及明确偏好，缺失偏好从重复记录补齐，扫描元数据和子会话标记取最新可用值；不同 source/environment/WSL 身份/importedSourceId 和未解析相对路径不能误合并。迁移结果原子落盘，现有备份机制保留原件；写入失败告警、保留修复后的内存结果及旧磁盘数据，下次启动重试。
3. **回归和门禁（已完成）**：首轮定向13项测试有8项失败，复现不可用聊天目录阻断启动、既有双记录未收敛及相邻边界；最终新增13项回归，覆盖目录恢复、读取/写回失败、偏好冲突、重载幂等性、身份隔离、父子关系及迁移失败重试。关联定向52项全绿。标准 `npm run typecheck` 通过；`npm test` 共3593项，3588通过、5跳过、0失败；`git diff --check` 通过。日志保存在临时目录的 `pideck-followup-*.log`，未暂存/提交。
