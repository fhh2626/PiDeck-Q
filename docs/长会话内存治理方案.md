# 长会话内存治理方案（轮次化历史模型）

> 适用范围：超长 Pi 会话的主进程文件读取、运行期缓存与渲染层窗口治理。
> 本文按维护性/性能修复后的实现同步；实测与环境限制见 [执行记录](maintainability-performance-execution.md)。常量以代码为准，不应把旧文档的 3/12 轮当作当前配置。

## 1. 目标与真实边界

- 以完整 user 轮次进行裁剪与分页，不为了资源指标切断有效对话。
- 避免冷启动、计数、压缩统计和全文定位反复读取/解析同一整个 JSONL。
- 保留稳定 session UUID、运行时 generation、entryId 锚点和历史游标的既有语义。
- **不是所有内存都具有常数上界**：展示索引元数据仍为 O(条目数)，完整单行/单轮正文也可很大。LRU 限制文件数量，不是全局字节预算；不能把这些边界宣称为恒定 RSS。

## 2. 单一数据链路

```text
renderer session atom（最近 8 会话 LRU、尾部窗口 + 临时历史前缀）
    → SessionRuntimeCoordinator（sessionId → 当前 runtime target）
    → AgentManager（尾部 50 轮运行期缓存）
    → SessionHistoryReader
    → SessionDisplayIndexStore（32 文件元数据 LRU） / JSONL 字节范围
```

- renderer 不直接读文件，不创建第二份全局历史缓存。
- Pi 仍拥有 Agent、工具、模型及会话协议；桌面通过原有 stdio JSON-RPC 访问 Pi。
- TS Pi 的 `agent_settled` 与 Rust Pi 的结束事件/状态确认路径保留各自兼容处理。

## 3. 运行期和显示窗口

- `MAX_RUNTIME_CACHE_TURNS = 50`：一轮结束或状态兜底确认空闲后裁剪运行期数组。
- `MAX_HISTORY_LOAD_TURNS = 50`：大历史首次文件加载的尾部轮次上限。
- `DISPLAY_WINDOW_TURNS = 50`：主进程 flush 的显示窗口轮数；这些值未在本次性能修复中调小。
- 裁剪按 user 起点，系统摘要卡片不占轮次并保留。数组下标空间改变后做全量窗口校准，不把旧增量索引应用到新数组。
- `messageHeadOffsetByAgent` 记录缓存头部在文件角色消息空间中的偏移；entryId 始终优先，数字偏移只作缺少锚点时的兜底。
- `readRecentMessages` 先在索引角色元数据上运行既有裁剪策略，再读选中正文；它不套用展示页的 256 KiB 预算，以免改变完整轮次与无-user 文件的兼容行为。

## 4. 共享文件索引

### 4.1 冷构建与缓存

`SessionDisplayIndexStore` 是单一索引 owner；Reader 负责正文转换与公开 API。

- 冷构建按 64 KiB 块流式扫描，分片行只拼接一次；每 256 行主动让出事件循环。
- 保留条目偏移、长度、角色、ID、父关系及压缩元数据，不保留所有历史消息正文。
- 同版本并发冷读共享构建，默认 LRU 为 32 文件。
- 内部版本包含 `dev/ino/size/mtimeMs/ctimeMs`；公开 `indexVersion` 仍为 `${mtimeMs}:${size}`，不更改跨进程游标协议。
- 活动分支采用最后同 ID 条目；全文查找保持物理第一匹配，含 legacy messageId；压缩统计覆盖物理记录，包括放弃分支及无 ID 记录。三种范围不能混为一种。

### 4.2 增长与改写

- 文件稳定时复用索引，不重新全量扫描。
- 增长不等于纯追加：旧首/末 ID 探针无法识别等宽的中间 parentId 改写。
- 尝试增量复用前，以有界缓冲验证旧前缀 SHA-256；匹配才追加尾部元数据，否则重建。
- **增长版本仍需 O(oldSize) 前缀 I/O**，不能宣称“所有 append 只读尾部”。这是保证分支身份正确的保守取舍。
- 构建及范围读取检查打开句柄和当前路径版本；避免原子替换后描述符继续指向旧 inode。文件在读取时变化则有界重试/返回本地化可重试错误，不返回混合快照。

### 4.3 分页与全文

- 选中条目按范围读取，相邻范围最多合并为 1 MiB；短读继续补齐，读取前后验证快照。
- 消息分页和轮次分页都以活动消息条目为坐标；压缩会话同样只读本页正文，在本页经过保留起点时补摘要卡片，不再声称整文件读取后切片。
- 轮次页按 user 对齐，256 KiB 为保留完整轮次前提下的软预算；单轮超大仍必须完整保留。
- 返回 `messages / total / nextBefore / nextBeforeEntryId / indexVersion`；优先使用 entryId 跨运行时/文件空间对齐。
- 全文查找索引命中后只读取目标条目。正文 LRU 上限 200，包含文件版本与显式 entry anchor；改写后不得返回旧正文。

## 5. renderer 缓存和多会话隔离

- `SESSION_MESSAGE_CACHE_LIMIT = 8`，淘汰仅作用于 renderer 缓存，不删除会话文件。
- `TIMELINE_MOUNTED_TURN_LIMIT = 50`：贴底时的 agent-run 挂载窗口；折叠工具/思考组不构建其全文 DOM。该常量并非本次新增优化。
- 历史前缀通过 `prependSessionHistoryPageAtom` 合并，按 entry key 去重；版本改变则失效。
- 回底稳定 1500 ms 后清理临时历史前缀，推进加载序号，拒绝清理前发出的迟到续页。
- `HISTORY_AUTO_LOAD_THRESHOLD = 8px`，每页 3 轮；程序化滚动标记防止 prepend 补偿引发连锁加载。
- Pane 命令采用最新已提交实现的稳定代理；Pane state 只投影本 session 的 agent、queue、duration、restart 信息。agent 按完整标量字段比较，而非依赖 inventory `.map()` 产生的对象引用，保证其他 session 更新不会破坏本栏数据等价性。全局 chrome、后台 Ask 通知等确实共享的数据仍可唤醒订阅者，不能宣称所有全局更新完全隔离。

## 6. 身份和压缩语义

- `activeEntryIds` 是给 Pi `get_messages` 结果对齐的角色消息向量：按最新活动压缩的 `firstKeptEntryId` 保留可见段，缺失锚点采取保守空向量。
- 离线展示索引仍包含活动分支中压缩点之前的历史；不要用上述向量裁掉离线历史。
- projector 按 user/assistant/toolResult 消费 ID 槽位，摘要卡片不占槽位；裁剪正文时同步裁剪 ID 向量，防止编辑/删除/重发落到错误条目。
- `tryReadRuntimeTurnPage` 检查会话路径及 entry anchor，缓存未命中回退文件。
- JSONL 的历史记录与模型上下文压缩不是同一范围；展示压缩摘要和定位 retained entry 不应复刻 Pi 的压缩行为。

## 8. 验证和限制

- 行为：`sessionHistoryReadResources.test.mjs`、`sessionHistoryReader.test.mjs`、`agentManagerRuntimeCache.test.mjs`、`sessionAtoms.test.mjs`、`sessionPaneServices.behavior.test.mjs` 等覆盖分支、改写、全文、页边界、缓存及双会话投影。
- 资源：`node scripts/benchmark-review.mjs`，只访问一次性 fixture。约 10/50 MiB 文件的 recent + count + compaction 冷组合累计读取约 10.67/52.60 MB，warm 全文约 10,335 字节；这是本地 Node 字节统计，不是 Qt/WSL 端到端延迟。
- 数字游标在缺少 entryId 时仍为 best-effort；匿名无文件会话无历史文件可翻。
- 首次索引仍需全文件扫描，显式全历史 API 仍可能读取全部选中正文，超大单行/单轮不具常数内存保证。
- Windows 文件锁不允许真实 rename-while-open fixture；对应 POSIX 路径替换以文件系统 stat 边界替身验证，不能替代 POSIX 安装包 smoke。
- 原生 HostRpc/GUI smoke 与资源单测分开报告；真实大历史 QtWebView profiling、真实 WSL、真实模型/Rust Pi 和跨平台 RSS/event-loop profiling 仍需专门环境验收。
